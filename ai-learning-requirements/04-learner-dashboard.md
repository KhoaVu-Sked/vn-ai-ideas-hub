# Feature: Learner Dashboard

Part of [ai-learning-requirements](00-overview.md) — read that first for the status-tag legend and how these files relate.

## 4.10 Learner Dashboard — ✅ Built (rebuilt this pass to follow a design mockup)
Lives at `/learning/dashboard` (`features/learning/LearnerDashboardPage.jsx`). Originally built alongside pulling the Mind map out of Your Journey ([03-your-journey.md](03-your-journey.md), 4.4); since rebuilt again to follow a design mockup (`AI Learning dashboards.html`, repo root) rather than the plain stat-tiles layout described in earlier drafts of this doc. Still reuses the same `GET /api/journey` fetch Your Journey already makes — no new endpoint, no new table.

**KPI row** — four tiles:
- **Roadmap complete** — % of what's expected by now (the same `isExpectedByNow`/`effectivePosition` scoping Your Journey uses: courses at or below the learner's own tier, plus one stage of early access once that tier's done) that's actually `complete`.
- **Level** — current position, plus the next rung up (e.g. "Target: Middle · 2 stages left"), or "Top of the ladder" once at Principal.
- **Weekly streak** — see below.
- **Ideas shipped** (renamed from the mockup's "Skills applied"): count of the learner's own Ideas Hub submissions (`my_roles` includes `Initiator`) with `status = 'Launched'`, hint showing how many they've submitted in total — deliberately narrower than the Application card below it (which also counts ideas joined in another role): this KPI stays "submitted by me" specifically. Named for what's actually counted, not an idea↔course link, so it can't say *which* skill an idea applied.

**Learning card — "Progress by level"**: a **display-only** regrouping of the same 5-tier position ladder into 4 named levels — **Foundations** (Intern), **Applied** (Junior), **Intermediate** (Middle), **Advanced** (Senior *and* Principal, collapsed onto one shared bar). Computed client-side (`progressLevelForPosition`/`rolesForProgressLevel`/`PROGRESS_LEVEL_ORDER`/`PROGRESS_LEVEL_LABEL`, all in `features/learning/shared.js`) by re-bucketing `courses.expected_by_position` at read time — **no schema change**, no `progress_level` column or table anywhere in the database (see [08-data-model.md](08-data-model.md)). Every gating/locking/ordering rule everywhere else in this feature — the Mind map's columns, the List view's tier-gated drag-drop, Team view's roster, every SQL query in `queries.js` — still reads the raw 5-value ladder exactly as before; this chart is the only place the 4-level regrouping exists. Below the level bars, **"My courses"** reuses `JourneyTable` — the *exact same* List-view component from Your Journey ([03-your-journey.md](03-your-journey.md), 4.4), same columns, same row-expand for the course link and outcome — not a second implementation of the same list. Its own track dropdown sits next to the "My courses" heading — always exactly one of the learner's enrolled tracks, no "All tracks" option, same rule Your Journey's own filter uses (4.3) — and scopes only this list, never "Progress by level" above it (still every enrolled track, unaffected — the two sit in the same card but don't share a filter). (No drag-reorder anywhere in this feature any more — removed, [03-your-journey.md](03-your-journey.md), 4.6.)

**Weekly streak** (the KPI tile, and repeated as "Current streak" on the Consistency card below): `weeklyStreak()` (`shared.js`) counts consecutive Mon–Sun weeks — ending at the current week, or last week if this week hasn't landed one yet — with at least one course completed, full stop (`course_assignments.status = 'complete'`). Auto Schedule booking a session is **not** a precondition — it's a scheduling aid for learner motivation, so a course finished with no calendar booking at all still counts. (An earlier version of this scoped the streak to `calendar_event_id` being set — dropped on the product owner's own call that Auto Schedule shouldn't gate the streak.) See [07-scheduler-auto-schedule.md](07-scheduler-auto-schedule.md) for Auto Schedule itself.

**Application card — "What I've built from what I learned"**: `getMyIdeas()` (`features/learning/queries.js`) — every idea the learner has any hand in, not just the Ideas shipped KPI's submissions-only scope: an idea qualifies if `ideas.initiator_account_id = me` OR the account has a row in `idea_members` for it (per-idea team membership, joining as e.g. AI Design or Tester rather than submitting). Each row carries `my_roles` — the account's own role(s) on that idea — so the card can say which one earned it a spot, not just list it indistinguishably from a submission. Still owner/membership + status only, same as the KPI: no idea↔course/skill link exists, so it can't say *which* course or skill an idea came from.

**Consistency card — "Learning activity"**: Courses completed, Hours logged (sum of `est_hours` on complete courses, all-time — not "this month": `course_assignments` keeps one `updated_at` per row, not a change history, so a monthly window isn't derivable), In progress, Current streak (same number as the Weekly streak KPI).

**Retention card — "Confidence by skill"**: `courses.skills` (migration 028, [01-course-catalog.md](01-course-catalog.md), 2.1) is a shared tag array — seven skills across the AI Track's 20 courses, plus a separate eight-skill taxonomy across Core Competency's 36 ([01-course-catalog.md](01-course-catalog.md), 2.2) — deliberately coarser than `courses.focus_area` (which stayed a per-course description, ~1:1 with the title, and isn't what this reads). Unscoped by track: a learner enrolled in both sees rows from both taxonomies in one list. One row per skill the learner has actually **completed** at least one course toward, each with a 5-segment confidence meter (`skillConfidence`/`SKILL_CONFIDENCE_SCALE`, `features/learning/shared.js`) — a skill with zero completed courses doesn't show a row at all, same "no fabricated numbers" rule as everywhere else on this dashboard; an in-progress course (started, quiz not done) isn't enough to seat a row either, on the product owner's own reasoning — a confidence number needs a real result behind it, not a course merely begun. Per course, the meter's input (`courseStrength`, `shared.js`) is: first-try quiz accuracy if the course is complete and has a quiz snapshot, full credit if complete with no quiz (5 of the AI Track's 20 catalog courses have none — Core Competency has full quiz coverage across all 36, [01-course-catalog.md](01-course-catalog.md), 2.2, so this fallback never actually fires there); not_started/in_progress/skipped courses are all excluded rather than counted as 0. A course tagged with more than one skill contributes to each. The skill rows scroll after 3 (fixed-height rows, `SKILL_ROW_H`, `LearnerDashboardPage.jsx`) rather than growing the card taller with every skill a learner's touched. Below the skill rows (outside that scroll, always visible), an "Avg exam accuracy" row (`avgExamAccuracy`, `shared.js` — named for what it is, the correct-answers-over-total-questions ratio, not a generic "score") averages the same first-try accuracy across every completed, quiz-graded course, unscoped by skill — same all-time scope as the Consistency card next to it. Unscoped by `isExpectedByNow`/track filters, also matching Consistency: a course finished early still earned its confidence.

**What's next card**: reuses Your Journey's own "upcoming" pick — dated soonest-first, then undated in roadmap order — for a "Finish course X" row (shown as its target date, not "from your calendar": a live calendar read is a separate lift not covered here, and `target_date` is real data either way), plus a second row surfacing the most recently completed course's own `outcome` copy as a "try this" nudge — no fabricated suggestions.

**Application · AI Ideas Hub card**: real now — every idea the learner has submitted (`getMyIdeas`), each a row linking to `/idea/{id}` with a status pill reusing the Ideas Hub's own `STATUS_META` colors (`features/ideas/constants.js`, imported the same way `features/learning/queries.js` already imports `POSITIONS` from `features/accounts/constants`). The idea↔course/skill link is still genuinely missing — nothing here can say *which* course or skill a given idea came from, so unlike the mockup's own "From Prompting + Summarizing" per-idea attribution, each row shows only the idea's name, number, and status. `GET /api/journey/ideas` is a separate small endpoint (not folded into `/api/journey`, which Your Journey also calls and doesn't need this).

**Kept from the previous layout, moved below the sections above** (unaffected by any of the progress-level or KPI work):
- **Mind map**: the same tier-gated view described in Your Journey ([03-your-journey.md](03-your-journey.md), 4.4/4.5) — same columns-by-position-tier layout (still position-grouped, not level-grouped), same Locked/Skip-prerequisite behavior and confirm wording, same `features/learning/MindMap.jsx` component Your Journey's "See the Mind map →" link also points to. Has its own track-filter dropdown, separate from "My courses" own filter above it — same "always exactly one track, no All tracks" rule, just a second, independent selection.

The per-track "Roadmap progress" section (one completion bar per enrolled track) that used to sit above the Mind map was removed — "Progress by level" (above, in the Learning card) already covers roadmap completion, just grouped by level instead of by track.

A nav link ("My Dashboard," in the app header, next to "Learning Hub") points here.

**Acceptance criteria:**
- [x] A learner with zero enrolled tracks sees the empty state, never a broken roadmap
- [x] Locked courses (Mind map) can't be worked around without Skip prerequisite
- [x] Skipped and not-started are visibly distinct from Complete/In progress
- [x] Reordering never crosses a stage boundary
- [x] Knowledge artifacts show real quiz results for completed courses, plus a nudge for what's in progress
- [x] Wrap-up is a real quiz that marks a course complete, not a placeholder button
- [x] Up next reflects a real scheduled plan *(Auto Schedule writes real `target_date`s from real Google Calendar events — [07-scheduler-auto-schedule.md](07-scheduler-auto-schedule.md))*
- [x] The Mind map and its Skip-prerequisite flow work identically on the Learner Dashboard as they did on Your Journey before the move
- [x] Roadmap complete / Level / Weekly streak (KPIs) and the Learning / Consistency / What's next cards show real, derived data — no fabricated numbers standing in for data that doesn't exist
- [x] Ideas shipped (KPI, submissions only) and the Application card (submissions + team-joined ideas, tagged with the account's role) — real, derived from `ideas.initiator_account_id`/`idea_members`/`ideas.status` only
- [x] Retention "Confidence by skill" — real, derived from `courses.skills` and each course's own status/quiz snapshot; a skill with no engaged courses is omitted rather than shown at 0
- [x] "My courses" and the Mind map each filter to exactly one enrolled track (no "All tracks" option, no combined-track view anywhere on this page) — independently of each other and of "Progress by level," which always stays scoped to every enrolled track
- [ ] Per-idea skill/course attribution ("this idea came from Prompting + Summarizing") — still blocked on an idea↔course link that doesn't exist anywhere in the schema; owner+status alone (above) can't answer *which* skill an idea applied
